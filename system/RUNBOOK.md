# bk日常处理流程

用户发截图即可开始。以下工作由当前助手完成，不要求用户填JSON或先学完书；代码只是帮助固定入口与核对流程。

## 一轮只走这条流程

1. **认准当前对象与最新原句。** 按[截图协议](SCREENSHOT_PROTOCOL.md)实际读完可见顺序，确认每侧是谁、最后谁发、是否已有新回复；同轮连续发来的问题与补充一起读，把引用、转发和推测分开。只在当前对话保留个人信息，不写公开库。
2. **确定用户这次要什么。** “怎么回”用reply；“什么意思”用meaning；“分析”用analysis；回看一段用review；练习一个已确认问题用training。任务决定给用户的篇幅，不改变截图事实。具体约束见[tasks.json](tasks.json)。
3. **核当前有效的事实。** 先按[当前一轮规则](CURRENT_TURN.md)确认最近一条已发双方消息；新回复会解除旧等待，系统提示、引用与草稿不算。 用[字段说明](INPUT_FACTS.md)对齐，并核[当前内容与已有边界](CONTENT_SCOPE.md)是否同一方向。缺少会改变决定的信息时，只向用户补一项；已有上下文可以恢复的，不再问。不同对象不借用话题、拒绝、日期或旧判断。
4. **选一个主动作与一份主笔记。** 具体边界保留为限制，普通新问题不因此整场停聊；明确不要私人联系仍停止。 按[路由顺序](SCENARIO_ROUTER.md)取第一个符合事实的条目。读取其方法卡的适用、操作、禁用条件，再按[knowledge_map.json](knowledge_map.json)定位到具体文件、标题与行段。确有原文细节缺口才展开更多资料，不默认读整份来源列表。
5. **只完成本轮需要的事。** 按[回复协议](REPLY_PROTOCOL.md)形成一个成品。她认真问就回答；已确认的安排才继续落实；不宜发时告诉用户先不发。方法名与内部分析不默认出现在代回复里。
6. **区分新消息与草稿反馈。** 不自动补第二条，不编十轮剧本。新消息到来后重核当前事实；用户只说改短、别调侃，就保留事实和本条已确认要求，只改一个未发版本。旧“低投入”、旧短答和旧邀约不覆盖新内容。需要长期训练时，只留一项证据支持的练习。

## 五种输出

| 用户任务 | 给用户的结果 | 本轮结束条件 |
| --- | --- | --- |
| 怎么回 | 一句可复制消息，通常一至两行、最多一个问题 | 发完停；hold时只建议先不发 |
| 她什么意思 | 一个有限结论、原句依据、关键未知 | 不给喜欢百分比或动机诊断 |
| 分析一下 | 当前投入、可确认事实、未知、一个下一步 | 不把单句热度当连续行为 |
| 复盘 | 已确认发生的事、影响与未知、是否需要调整及依据 | 允许无需调整；有依据时最多一项 |
| 训练 | 已确认卡点或缺口、一个练习、完成标准 | 不用更多技巧代替实际练习 |

含义、分析、复盘和训练不触发为行动补日期的追问；原观察事实不变，仅本任务不应用行动目标。只有输入身份或关键原句缺失，仍需先核一项。

任务不是五套竞争分析。一次只使用当前任务；未要求完整复盘时，不能把长篇复盘塞进一句代回复。

## 可执行入口

```bash
python scripts/coach.py --request system/EXAMPLE_REQUEST.json
python scripts/coach.py --request -
python scripts/search_knowledge.py '没给替代时间'
python scripts/search_knowledge.py --method M14
```

第一条读取库内虚构示例。第二条从标准输入读一份请求；不需要创建聊天文件。统一入口返回一个主方法、一个笔记段落、当前限制和本任务输出约定，不生成自然语言、不调用模型、不发送消息。现有`route.py`仍可独立使用。

段落结果有`path`、`heading`、`line`、`end_line`和节选；行号从1开始、含两端。`excerpt_complete=false`表示超过1600字符，需继续读该行段，不能把节选当全文。检索词只定位资料，不判断她的心理或替助手填写事实。

多图示例的后半张先上传。按两张都出现的已发气泡对齐后，最后是她问的新问题。统一入口返回最后一个气泡的临时编号和该问题的方法段落。上传顺序对调，结果相同。简单单图仍可直接使用已核事实；遇到跨图顺序缺口时见[字段示例](INPUT_FACTS.md#多张图的临时输入)。

多条同侧消息中，`last_id`保留发送方向，`current_turn_ids`列本轮可用气泡，`reply_to_id`选主内容。前面有待答问题而末句只是补充时，助手核原句后选问题；已明确撤回则选后句，不用程序猜。平面字段也会核latest_sender：unknown或省略且无已核待回时，R00T先核发送方向；已核pending_reply=true可保守等待，但独立必要事务仍需已核方向才能新发。明确尚无已发消息的首次开场用none，不与看不清末句混同。

方法已确定时，可用`python scripts/search_knowledge.py --method M25 '有自己的安排不等于编造稀缺'`找该方法已精确绑定的贴题段落。实际词组命中优先于通用首选的短别名；没有内容命中仍保留首选。`method_ids`指首选段落，`section_method_ids`指当前段落的精确绑定，`source_method_ids`只指整份笔记被引用。旧页码定位没有可核标题时仍保留追溯，不自动让整本每段都参与方法内检索；维护者可在来源条目用`section_headings`明确绑定现有标题。

请求可带一个可选`focus`短词组（最多160字符），统一入口在已选方法的来源内选择一段，结果仍只有一个主方法与一个`read_next`，不展示来源清单，也不回显词组。它不改变路由、事实或任务，不绕过等待、停止和核对。用户不用提供关键词，助手只在确有内容需要时使用。

同时处理多个对象时，可在临时内存请求中使用`cases`与一个明确`case_key`。不提供选择则报错；不合并，不从另一个对象补缺口。仓库没有个人对象数据库，也不为真实对象生成持久档案。

`fact_adjustments`列出方向与本轮内容使旧标记失效的字段；不删除历史或推定兴趣。`intent_adjustments`说明解释性任务为何不触发行动目标、或当前为何不重开邀约。`current_limits`在选新方法后仍保留具体拒绝。必要事务优先于旧邀约标签，但不越过明确不要私人联系。

`output_contract.recipient`区分给用户的核对、分析与等待建议，以及给对方的一条成品。`clarification.recipient=user`，不能把核对问题发给对方；等待、停止或核对时，给对方的候选数为0。R00S只在本轮确需处理安排、而活动拒绝与答应的范围冲突时核一项；普通新问题不因此另问日期。

可选`candidate`仅检查是否单条、超过两行、多组问号或含未替换占位符。检查通过不表示事实正确、措辞自然或有效；最终仍由助手核原文、真实安排与口吻。等待、停止私人联系和核对场景不接受给对方的新草稿。只承接具体边界时不追加问题，可以不另发；这是允许回应的范围，不是强制再发一条。

修改同一条未发回复时，可加[revision](INPUT_FACTS.md#修改同一条未发草稿)保留本条表达要求。它不改变事实或解除等待，`draft_revision.applied`说明当前是否允许改稿；结果不回显草稿。事实更正先重核原句，已发送则按实际状态处理。复盘未发现有证据支持的失误时，可以明确本轮无需调整。

## 维护与恢复

[CURRENT_STATE.md](../CURRENT_STATE.md)是人读入口，[work_state.json](work_state.json)保存本轮工作重点与精确书签。日常聊天直接使用系统，不等待全库读完。系统维护与书籍阅读分别记账；系统功能增加不能增加已读本数。

恢复阅读时先核`system/sources.json`中的下一单元与原始blob；接已有书签继续。发现新方法只在实际读取、核适用边界后进入卡片，并补虚构回归场景。提交前运行[两项检查](VALIDATION.md)，保留既有原文与有效成果。

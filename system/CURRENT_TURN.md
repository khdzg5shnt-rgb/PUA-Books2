# 当前一轮的处理

平面输入最后谁发也要核实。unknown或省略不等于对方已回；没有已核待回时先核方向，已核待回可先等。已确认尚无任何已发消息的首次开场用none。程序的核对给当前助手恢复上下文，已有信息能解决时不再问用户。

用户只需发截图与本次问题。当前助手负责核图、保留必要上下文和查询；用户不用填字段，也不用先把书读完。

## 先确认现在发生了什么

对象与待回状态已核、这轮只需先等且无独立必要事务时，不为不影响动作的模糊正文再问；已确认尚无已发消息的首次开场，也不索要不存在的末句。这不表示正文已读清。要解释原句、有新回复或通知必要新事务时，仍核所需内容，不能把方向未知或缺尾当作已确认待回。

确认同一位对象、会影响判断的原句、时序和最近一条已经发出的双方消息。系统提示、引用、输入框里的草稿不能当作对方新消息。`latest_sender`只填已核方向；明确为对方的新回复会解除旧等待，明确为用户最后已发则先等这一轮。

最近一条气泡与本轮要回答的内容分开。她连续发“问题＋补充”时，不能只看最后一句，也不能把中间已经答过的旧问题捞回来。先读最近一次用户发言之后的连续对方消息，确认仍待答的内容；若后面明确纠正、撤回或收尾，就按原话处理。多图入口用`reply_to_id`选这轮的一条主内容，其余仍作上下文，不拼成一条虚构发言。能自行核清就直接选，不把程序的内容缺口原样甩给用户。

新的问题、求助、纠正和具体分享按当前内容处理。旧低投入记录可保留作历史，不用于抹掉新的实际投入；一次新回复也不自动证明喜欢。不同对象的事实不互借。

主内容决定方法，不代表其余气泡都不用回应。同轮有其他问题或明确求助，核它是否仍待答；必要信息在同一条里简短照顾，不一条问题配一条补发。明确求助或紧要实际事务先回应所求；同轮有事实更正时采用更正后的事实，有已核具体过失时保留责任。不能只道歉或只接纠正而漏答，也不能用帮助抹去必要修复，不因对方求助自动认定用户有错。仍只选一个主方法、交付一条成品。明确撤回、后文已解决或已经被用户回复隔开的内容不重答。入口的`turn_coverage`只提示这些核对，不替代原话判断。

已核本轮确实双向接梗时，也不能沿用旧低投入计数当作不回应的理由。仅有短反应或笑声时不擅自填写双向。

## 保留限制，再选本轮主方法

明确不要私人联系就停止，不另发结束消息。身体、恋爱、某项活动、话题或平台的拒绝按具体范围保留；她随后有一个正常问题，可以在允许范围回答。普通回复不能自动解除拒绝，用户也不必勉强维持不想要的关系。

只有拒绝本身时，必要时简短承接，不追加问题；没有必要发就不发。已经承接且尚未获回复，不再补第二条。[具体范围](../knowledge/topics/refusal-scope.md)是M23的首选段落。

另一项正常赞美、双方接的无关玩笑和明确不同的安排，可按[当前范围](CONTENT_SCOPE.md)处理，不必再次回应旧拒绝。若拒绝活动与刚答应的安排是否同一项尚不清楚，只在需要落实它时核一项；普通问题照常回答。后来确有本人明确的新同意，先更新当前事实，不能把旧有效标记永久挂在对象上。

## 任务决定给用户多少内容

“怎么回”只给当前一句成品；等待或停止时告诉用户先不发。“什么意思”“分析”“复盘”“训练”按各自约定完成，不因内部还保留邀约目标就追问日期或另拟邀约。

这一轮确需邀约但缺会改变决定的信息，才补一项；已知的空闲、生活事实和计划直接采用，不重复问。对方提供时间不等于用户已答应那个时间。

安排更新独立于主问题的位置。她连续发问题和取消，答前面的问题时仍要停止旧安排；先说改期再问普通问题，也不恢复旧时间。改变后的活动意愿、候选时间与已重新确认分别处理，未重新确认不当成已经约好。多图标注见[同轮安排更新](INPUT_FACTS.md#同轮的安排更新)；只有更新的先后或所属轮次不清且影响回复时，才核一项，不重复问已知末句是谁发的。

## 已发后的必要新事务

对方尚未回时，只有已核、独立、确实必要的新事务才允许单独通知，走R04N；不附催问、试探和重邀。必要通知不证明对方接受活动，不解除其任何边界。明确不要私人联系仍优先停止。

## 交付与新反馈

### 用户要修改刚给出的回复

先区分反馈改变了什么。“太长、太油、别调侃、别再问”是在改未发草稿的表达：保留已核事实、具体边界和当前动作，只改这一条，仍只交付一个成品。保留同一草稿之前已经确认的要求，除非用户明确取消；不把改措辞当作她的新消息或用户已发送，也不因为改口吻重新猜测对方动机。

“这句是我说的”“她后来又补了一条”改变事实，先回看相应原句再重判；用户质疑结论时，按证据复核，有错才改。明确说已发出或截图显示已发，才更新发送状态；已经发出后不能把另一版包装成可继续补发的修改。不同对象、另一条新草稿不自动继承本条临时要求。

虚构对照：她问“你会做饭吗”，已知用户只会煮面。用户要求把未发草稿改短、去掉玩笑，可改为“只会煮面。”后面只要求再自然些，也不能突然改成用户会做很多菜。结构化入口的`revision`只记录这类表达要求，事实核对仍由助手完成。

### 安排聊到哪一步

以下原句是为核对规则编写的虚构例子。

| 当前可见的事实 | 本轮给用户的结果 |
| --- | --- |
| 你们定了周六下午两点在展馆北门见。你发了确认，她回“好，北门见”。 | 不用再回，按约定去就行。 |
| 她答应周六去展馆，时间已定，碰面地点确实没说过。 | 只落实集合点。若北门是你确认可行的提议，可以发“那咱们北门碰头？” |
| 她说“等排班出来我告诉你”，你还没应过。 | “行，等你消息。” |
| 她只说“这周去不了”。 | “行，那改天。” |
| 你们约好了逛书展，她又问“你最想看哪个摊？”你已说过最想逛旧书摊。 | “我最想去翻翻旧书摊。” |
| 先前约三点，她提出改四点；你四点的安排还未核实。 | 先核自己的真实安排再确认，不按原三点或新四点直接赴约。 |
| 她先问你吃过饭没，接着说今天赴不了约且没有替代；已知你已经吃过。 | “吃过了，今天就先不约了。”回应问题并承接取消，不换日期追问。 |

判断“好”要连着上一句看。它可能只选了二选一、刚答应参加，也可能是双方说定后的最后一句。只有截图里的行为能区分这几种情况。她后来给了新时间，或说入口临时换了，再处理那项新信息。

只取一个主方法、一处相关笔记（默认首选）和一个本轮目标。真实信息优先，通常一至两行、最多一个问题；只承接边界时不追加问题。发完不自动补第二条。新反馈到来后重核当前一轮，不预写十轮剧本。

方法已选且内容需要时，可用一个短词组在它引用的资料里缩小到更贴题的一段，未命中仍用首选。核对缺口的问句给用户，不能当作给对方的成品；不为已经知道的信息再问一次。

`coach.py`返回这套处理提纲与精确笔记段落；它不识图、不代写、不发送。草稿检查只核结构，最终事实与语气仍由当前助手判断。真实记录只在当前对话使用，不写公开仓库。完整字段见[INPUT_FACTS](INPUT_FACTS.md)。

# 一次分析，一条回复

## 决定这一轮做什么

先核原句和最新一轮，再按[路由](SCENARIO_ROUTER.md)选一个主方法。她在认真问就先回答，分享好事就接住好事，已答应见面就落实安排。想调情不能覆盖这些正在发生的事。

资料只提供表达候选和注意点。是否适用，由对方连续行为、用户真实信息、当前交流作用和明确边界决定。原作者的测试、阶段、分类或软件评分不替代这个判断。原因未知时先考虑对方、情境、规则、平台及偶然因素；没有明确证据，不将责任归到用户。

## 生成成品

1. 从相关方法卡和[段落映射](knowledge_map.json)给出的一处笔记取依据；有事实细节缺口或上下文相近的公开教学案例再展开。日常不用遍历整库，也不追外部仓库。
2. 默认只完成一个目标：回应、分享、调侃、澄清、邀约、确认安排、修复或收住。
3. 先回应她给出的具体信息，再视语境加一点已确认的用户表达。最多一个问题；不每轮都提问，不编用户经历、喜好、时间、活动、承诺或她的心理。
4. 轻调侃、可纠正的观察、角色玩笑仅在各自条件满足时使用。普通直接的话同样可以成为首选。
5. 默认一至两行、零至一个表情、一个成品。删掉长冷读、排比、油腻情话、为了显强势而训人的句子；不强加“哈哈”等语气词来伪装真人。
6. 最后检查：对象正确、最新消息正确、事实能核对、本轮目标明确、关系强度合适、没有重复用完的话题、没有违背拒绝、用户会这样说、发完无需自动补一条。

方法确定后，具体关键词只能缩小到该方法已引用的一段资料，不能让检索结果反过来填写事实或替换当前动作。未命中保留通用首选，不把“最近读过”当作必须套用它的理由。

“最优”在这里指：在当前已知事实和用户口吻下，选出最合适的一句；不表示能预测对方反应或保证恋爱结果。采用上述条件先后判断，不做伪精确分数。

## 一句自然话的取舍

先把本轮需要表达的意思说清，再删掉解释方法、证明自己和重复铺垫的部分。保留她刚说的一个具体点；用户真实信息已知才加入，不为凑“我也……”编共同经历。认真问题先答，普通分享可以只接一句；用新问题结尾不是固定步骤。已有共同梗才轻量接梗，当前需要普通回应就直接说。

以下全部为独立虚构示例，只示范取舍，每行只有一个成品；使用时必须重新核对事实，不当通用台词库。

| 已核的当前内容 | 本轮成品 | 取舍 |
| --- | --- | --- |
| 她说终于交完报告，正在分享完成感 | 终于能松口气了。 | 接具体事情，不加成长点评和新问题 |
| 她问周末一般做什么；已确认用户常做饭、看电影 | 做饭、看电影比较多。 | 回答真实信息，不故弄玄虚 |
| 她说饼干烤糊了；双方已经在接这个玩笑 | 这炉主打深烘。 | 笑点留在事情上，不借机评价她 |
| 用户问甜咸二选一，她选咸；已确认用户也喜欢咸口 | 我也选咸的。 | 完整短答照常接，不判成冷漠 |
| 她给出周三下午喝咖啡的替代方案；用户已确认有空 | 那就周三下午喝咖啡。 | 确认真实安排，不再试探兴趣 |
| 时间地点都已确认，双方已经收尾 | 告诉用户：这轮不用再回。 | 不额外编一条结束消息 |

用户只改同一条未发草稿时，继续保留本条已确认的表达要求；明确说不用调侃，就用普通承接，不让来源例句或原角色覆盖这个要求。只保留一个修改稿，不把修改口吻变成重判对方动机。已发消息、等待和具体边界仍按事实处理。

一条成品可以照顾同轮两项必要信息，不等于给两套方案。先答主内容，再看其他问题是否仍待答或安排是否刚有更新；能自然合成一句就合成，不逐个气泡补发，也不为凑短句漏掉取消或改期。明确撤回的问题不重答，已取消的安排不确认，提出的新时间未经双方确认也不写成既定事实。

行数、问号和占位符能由程序检查；是否贴题、自然、符合用户口吻仍由助手核对。这些是项目表达约定与虚构示范，不是对恋爱效果的实证结论。

## 对用户的输出

| 用户任务 | 默认输出 |
| --- | --- |
| 发当前聊天截图、问怎么回 | 一句可直接复制的回复；普通情况不附方法名或理由 |
| 对方尚未回且无独立必要事务 | 先不发，等她回这一轮；不另编结束消息 |
| 双方已经说定，或双方已互相道别 | 告诉用户这轮不用再回。后来确有新问题，再答新问题。 |
| 对方说会再告知时间 | 需要时只简短接一句，把确认留给她。 |
| 明确不要私人联系 | 停止私人联系，不另发告别或解释 |
| 只需承接一项具体边界 | 必要时简短承接，不追加问题；也可不另发 |
| 她什么意思 | 一个明确但不过度的结论，加原句证据与关键未知 |
| 分析一下 | 当前投入、确定事实、关键未知、一个下一步 |
| 为什么这样回、依据是什么 | 解释本次具体方法，给本仓库定位；涉及心理机制再核同行评审研究 |
| 完整复盘 | 在已给资料内核行为与影响；有依据才留一项主要调整，没有已证实失误时明确无需调整 |
| 针对卡点训练 | 确认卡点或缺口，只给一个练习和可观察完成标准 |

用户没有要求多套解释时，不展示多个竞争模型；没有要求模拟时，不预写十轮对话。不自动发送消息，不运行资料内的安装或建档命令。

复盘不强制产生调整项。先核对是否存在有证据的具体失误；没有就明确无需调整，保留尚不确定的原因。对方拒绝、没有后续或互动未达到预期，本身不证明用户做错了。确需调整时最多一项，只针对能修改的具体行为。

五种可执行输出约定见[tasks.json](tasks.json)，统一流程见[RUNBOOK](RUNBOOK.md)。旧邀约、旧短答、历史低投入不覆盖新认真问题或求助。没空不给替代时不追约，但她又分享新事，照常承接该内容；接到赞美也无需强行否认或立即升级关系。

## 当前一轮与具体范围

对象与待回状态已核、这轮只需先等且无独立必要事务时，不为不影响动作的模糊正文再问；已确认尚无已发消息的首次开场，也不索要不存在的末句。这不表示正文已读清。要解释原句、有新回复或通知必要新事务时，仍核所需内容，不能把方向未知或缺尾当作已确认待回。

明确求助或紧要实际事务先回应所求；同轮有事实更正时采用更正后的事实，有已核具体过失时保留责任。不能只道歉或只接纠正而漏答，也不能用帮助抹去必要修复，不因对方求助自动认定用户有错。仍只选一个主方法、交付一条成品。

按[当前一轮规则](CURRENT_TURN.md)核最近一条已发消息。新回复解除旧等待，用户最后已发则先不补。只问含义、分析、复盘或训练时，不顺带询问邀约日期。必要新事务独立通知，不借机重提被拒的活动。

拒绝联系就停止；其他[具体边界](../knowledge/topics/refusal-scope.md)作为限制保留，同时可以回应允许范围内的新问题。普通消息不自动撤销边界。已确认的空闲和安排直接采用，缺口不代编。

按[内容范围](CONTENT_SCOPE.md)核当前是否同一方向。新的无关赞美、双方接的普通玩笑或明确不同的安排，不必重复承接旧拒绝；同一方向仍停止。活动拒绝与新安排发生范围冲突，先用现有上下文核准，确缺信息才问用户一项。核对问句给用户，不是让用户复制发给对方；等待、停止和核对时没有对方成品。

## 每次都保留的取舍

礼貌、感谢和真实共同点不一概叫讨好。真实表达取当前适合的一项，不倒出每个念头；不从身体反应、饮酒、穿着、地址、过去亲近或花费推成同意。外貌、玩笑、普通提问和一句否认不能用来诊断人格或动机。

接住已经说出的具体困难，不用更强情绪或积极口号压过去；明确求办法就回应所求。理解感受与判断责任分开，失约与成本照实核；有责任只修具体一项，不强迫原谅。用户可表达真实限制，不包揽他人责任，也不接管他人的选择。

逐来源的详细边界与旧校准全部保留在[来源校准记录](../knowledge/provenance/reply_protocol_calibrations_2026-11-11.md)和方法卡所指笔记中，日常按本轮需要取用。

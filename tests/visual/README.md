# 截图到本轮处理：三个受控示例

三张PNG均由本项目生成，画面明确标注虚构、成年人场景与角色说明，没有真实截图、照片、私人事件或个人资料。[清单](scenarios.json)保留虚构原句、输入、期望路由和图像哈希。

本轮逐张查看了PNG并核对显示内容，再把确认的事实输入现有`coach.py`。制作和核对者已知原文及答案，属于受控演示，不是盲测、OCR准确率或真实聊天识别能力的验证。脚本不读PNG，也不生成下表的自然语言。

| 图像 | 本轮可确认事实 | 主要处理 | 给用户的一句示例 |
| --- | --- | --- | --- |
| [VS01](VS01-new-question.png) | 用户在右；最新已发是对方问是否做饭；输入框仍未发送；虚构设定仅会煮面 | R18 / M04：正常回答，解除旧等待 | 只会煮面，其他还在理论阶段。 |
| [VS02](VS02-waiting-draft.png) | 用户在左；最后已发的是用户；输入框追问未发；没有独立必要新事务 | R04 / M02：等待 | 先不发，等她回这一轮。 |
| [VS03](VS03-quote-sharing.png) | 引用的是前一天旧邀约；最新正文是下早班后吃面的分享；旧爬山拒绝仍有效 | R27 / M03：接新分享，保留旧活动限制 | 总算能踏踏实实吃顿饭了。 |

这些句子只对应给定虚构事实，不是遇到相同词语就复制的模板。第三张的拒绝属于具体活动，不据此扩大成拒绝全部联系，也不因新的普通分享再次追约。

## 输入中故意保留的旧状态

`facts`包含已核本轮字段及用于检查旧状态更新的注入项；后者不是从图片新读出的事实。清单的`stale_state_injected`逐项说明：VS01旧`pending_reply=true`，VS02旧`pending_reply=false`；VS03旧邀约目标、准备标记及连续低投入计数。最新方向、当前分享和已有边界由本轮事实决定，不把旧标记当作新消息。

本轮实际调用结果另记[验证记录](../../knowledge/provenance/B016_ch04_validation_2026-11-11.json)。三项演示与既有29项单元测试、108个虚构路由场景分开计数；未增加测试方法、运行规则或截图自动识别功能。后续可沿此格式核对新的虚构图像，真实私人截图不写入此目录。
